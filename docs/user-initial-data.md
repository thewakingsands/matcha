# 用户初始数据

## 数据布局

服务端 `PlayerSetup` 的布局按 `FFXIV-Packet-Dissector` 的
`packages/network/src/definitions/ipc/player-setup.ts` 定义读取。
payload 至少 2951 字节，允许附加尾部数据。以下偏移均相对于 payload 起点。

| 字段 | 偏移 | 长度 | 读取方式 |
| --- | --- | --- | --- |
| 角色名 | `0x34C` | 32 字节 | UTF-8，以零字节结束，最多读取 32 字节 |
| 普通钓鱼 | `0x771` | 191 字节 | 字节内低位优先，位索引为 `FishParameter` 行号 |
| 刺鱼 | `0x85B` | 38 字节 | 字节内低位优先，位索引加 20000 为 `SpearfishingItem` 行号 |

两张表通过随插件分发的 `data/fishing-notebook.json` 映射到物品 ID。
值为零的条目不导出，已置位索引缺少映射时整份快照不可导出。
收到截断包后快照不可导出；后续有效包可整体替换当前快照。

快照仅保存在当前插件运行期间，不随区域切换清空，不累加后续鱼获。
保存对话框打开时固定所选快照；此后收到的新快照不影响这次导出。
保存取消时不提示错误，写入失败时保留快照并显示错误。

## 文件格式

默认文件名为 `fishcake-completion.json`，使用 UTF-8 和格式化 JSON。
文件字段严格为以下三个；`completed` 仅包含正整数物品 ID，去重并升序排列。

```json
{
  "completed": [],
  "pinned": [],
  "alarmFish": []
}
```

## 自动验证

需要 Node.js 22 或更高版本、.NET 8 SDK。在仓库根目录运行：

```sh
node --test utils/update-data.test.mjs
dotnet run --project tests/InitialData
```

独立测试入口直接编译生产环境的包读取、快照存储和导出代码。
人工数据覆盖位图首尾、跨字节位、刺鱼索引偏移、物品映射、去重排序、
空结果、缺失映射、截断与扩展包、快照替换、切图保留、插件重载清空、
并发更新、固定快照保存、文件写入失败，以及严格的三个导出字段。
数据更新脚本使用模拟接口验证字段请求和生成的鱼种映射。
测试不使用真实抓包或玩家信息。

## Windows ACT 验收

1. 使用仓库的 Windows 构建流程生成并加载插件。
2. 打开“用户初始数据”页签，确认尚未收到快照时显示重新登录提示，导出按钮禁用。
3. 重新登录游戏，确认角色、时间和完成数量更新，导出按钮可用。
4. 切换区域，确认快照保留；重新登录另一角色，确认快照整体替换。
5. 点击“导出鱼糕钓鱼笔记”，确认默认文件名，检查保存文件可导入鱼糕。
6. 取消保存，确认无错误提示；选择不可写位置，确认显示错误且快照保留。
7. 在保存对话框打开期间接收新快照，确认保存的内容仍属于打开对话框时的快照。
8. 重载插件，确认快照清空，导出按钮禁用。
